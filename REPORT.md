**2.1 Problem Statement**

*	For this design project, our group defined the problem to be the process of planning and designing, then creating and thoroughly testing a Model View Controller website using proper industry standard testing practices covered in class. Constraints also apply, which we must consider and follow several of them; these include: Economic factors, Regulatory compliance, Reliability, Sustainability and Environmental Factors, Ethics, and Societal Impacts. Due to the nature of the project, the focus of the project is to gain practical experience using several different testing and validation techniques, including Boundary value testing, Equivalence class testing, Decision tables testing, State transition testing, and Use case testing. As well, two functions must be tested; using Path testing and Data flow. During this process, we will follow the structured engineering design process; such as considering requirements, research, and brainstorming. Including analyzing and iterating on potential functions and prototypes. One important idea we are considering is whether to have accounts, which has a large upside, and some downside to implementing, and our process will prototype and test it. Our approved topic/idea for this project is Group Leader, a scheduling app for groups. Each member adds their schedule and availability, then the program will find common times between them, allowing the group to all pick a preferred time. This has a lot of use cases, including just for friend groups to meet, or even in workplaces, when they would need to schedule a meeting. Our first objective is societal impacts, which is to create this website, which will allow users to easily schedule times for meetings between busy schedules. It should be intuitive, quick, and user should have an easy time inputting their schedules. We also aim to meet regulatory compliance and user security risks, by either finding a solution for a secure log in, or avoiding storing schedule information. For reliability, we aim to take advantage of the testing cycles to ensure reliable and stable user experience. For economic factors, we are hoping to complete the project with spending no money, and if databases are required we will try to host locally, the product will also be free. Delegating work is another area for this project, where we will track which group member contributes individually. During the development cycle, we will document this process thoroughly, including test cases we use, commenting code, and having a public github.

**2.2.3 Constraints**

**Economic Factors** - Our project is free/inexpensive to complete, but must be fully completed by December 3, with a check-in on October 8. This limits our scope by limiting how much time we have to build our project.

**Regulatory Compliance** (Security & Access) - If Group Leader is to have any identifiable or personal information (such as with accounts), it is a high priority to minimize risks of vulnerabilities in the software. 

**Reliability** - We need to ensure that Group Leader is reliable, and that there will not be problems. It should be able to successfully complete all needed functions without issue.

**Sustainability & Environmental Impacts** - Group Leader should be easily sustained without any noticeable footprint. 

**Ethics** - The project must not cross any ethical boundaries. A focus on safety/security should solve any ethical problems with the design, but that does not mean other issues cannot arise and we will plan our project to ensure this is not a problem.

**Societal Impacts** - The project itself is relatively light, when it comes to societal impacts either way. One potential issue is misuse of data the site is given, which we will ensure is not going to happen.
